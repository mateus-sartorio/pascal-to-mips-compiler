# Pascal to MIPS Compiler

Academic project implementing a compiler for a subset of the Pascal language (based on the **ISO 7185** standard, available at `docs/iso7185.pdf`), generating **MIPS** assembly code that runs on the **MARS** simulator.

The project is written in **Java**, uses **ANTLR4** to generate the lexical and syntax analyzers from `.g4` grammars, and implements every remaining compiler stage by hand (semantic analysis, AST construction, interpreter and code generator).

## Compiler workflow

The entry point is `src/Main.java`, which takes the path to a `.pas` file and an optional flag telling it what to do with the file. The pipeline is always the same up to semantic analysis; from there on, the flag picks which "backend" runs:

1. **Lexical analysis** — `PascalLexer` (generated by ANTLR from `src/PascalLexer.g4`) reads the source file and produces the tokens.
2. **Syntax analysis** — `PascalParser` (generated from `src/PascalParser.g4`) consumes the tokens and builds the *parse tree*. On a syntax error, compilation stops here.
3. **Semantic analysis** — the `SemanticChecker` class (`src/checker`) walks the parse tree, validates types and semantic rules, and fills the symbol tables: global variables, procedures/functions (both declared in the program and built-in) and string literals.
4. **AST construction** — `AstBuilder` (`src/ast`) walks the parse tree again, this time using the tables from the previous stage, and builds the program's Abstract Syntax Tree (`ProgramNode`).
5. From the AST, there are two possible paths:
   - **Interpreter** (`src/interpreter`) — runs the program directly by walking the AST. Useful for validating a program's semantics without worrying about code generation.
   - **Code generator** (`src/codegenerator`) — walks the AST and emits equivalent **MIPS** assembly, ready to run on the **MARS** simulator.

The flags `Main` accepts (as its second command-line argument) are:

| Flag | Effect |
|---|---|
| `-print-tables` | Prints the symbol tables built during semantic analysis |
| `-print-ast` | Writes an `actual_result.dot` file (DOT notation) holding the AST |
| `-interpret` | Runs the program through the interpreter |
| `-compiler` | Emits the MIPS code into `actual_code_result.asm` |

All of these stages are exposed as `Makefile` targets, described further down.

## Repository structure

```
├── Makefile               # drives the build, the runs and the tests
├── src/
│   ├── PascalLexer.g4      # lexical grammar (ANTLR)
│   ├── PascalParser.g4     # syntax grammar (ANTLR)
│   ├── Main.java           # entry point, drives the pipeline
│   ├── checker/            # semantic analyzer
│   ├── ast/                # AST construction
│   ├── interpreter/        # interpreter (runs straight off the AST)
│   ├── codegenerator/      # MIPS code generator (off the AST)
│   ├── tables/             # symbol tables (variables, routines, literals)
│   └── types/              # the language's type system
├── libs/
│   ├── antlr-4.13.2-complete.jar   # ANTLR, bundled in the repository
│   └── Mars4_5.jar                 # MIPS simulator used to run the generated .asm
├── tests/                  # automated test cases, one subdirectory per stage
│   ├── lexer/  parser/  semantic/  ast/  interpreter/  compiler/
│   └── .../valid|invalid/<case-name>/source.pas + expected output
├── test.sh                 # main script, called by "make test"
├── test_compiler.sh        # runs the code generator suite (MIPS + MARS)
├── test_lexer.sh, test_parser.sh, test_semantic.sh,
│   test_ast.sh, test_interpreter.sh   # standalone/legacy versions of each suite
│                                        # (the Makefile does not call them, but they
│                                        # can be run on their own with "bash <script>")
└── docs/
    ├── project_specification.pdf       # the assignment specification
    ├── iso7185.pdf                     # the Pascal standard used as reference
    └── AST Class Diagram.jpg           # class diagram of the AST
```

## Requirements

- A **JDK** installation (Java compiler and runtime).
  > JDK 25+ is recommended, via [SDKMAN](https://sdkman.io/):
  > ```bash
  > curl -s "https://get.sdkman.io" | bash
  > sdk install java 25.0.2-tem
  > sdk use java 25.0.2-tem
  > ```
- **Graphviz** (`dot`) installed — needed to render the AST `.png` images (`make run-ast` and the AST tests).
- **ANTLR** already ships with the repository (`libs/antlr-4.13.2-complete.jar`) and is wired into the `Makefile` — there is nothing extra to install.
- **MARS** (the MIPS simulator) also ships with the repository (`libs/Mars4_5.jar`), and is used to run the generated assembly and to drive the compiler test suite.
- *(Optional)* **Free Pascal Compiler** (`fpc`) — only needed for the `run-pascal` target, which compiles and runs the original `.pas` with a real Pascal compiler. Handy for checking by hand whether a test's expected output is right.

## Building the project

Run every command from the root of the repository.

```bash
make
```

That is the `all` target, and it does two things:

1. **`antlr`** — runs ANTLR over `PascalLexer.g4` and `PascalParser.g4`, generating the lexer/parser Java classes inside `src/parser`.
2. **`javac`** — compiles every `.java` in the project (including the ANTLR-generated ones) into `java-bin/`.

To wipe everything the build produced:

```bash
make clean
```

That removes `src/parser`, `java-bin` and `bin`.

## Running the compiler by hand

Every target below takes its input Pascal file through the `FILE` variable.

```bash
# Run the lexer only and print the tokens it produced
make run-lexer FILE=path/to/file.pas

# Run the parser and print the parse tree as text
make run-parser FILE=path/to/file.pas

# Same as above, but opens a window with the tree (handy for local debugging)
make run-parser-gui FILE=path/to/file.pas

# Run the semantic analyzer and print the symbol tables
make run-semantic FILE=path/to/file.pas

# Build the AST and write actual_result.dot / actual_result.png (via Graphviz)
# next to the input file
make run-ast FILE=path/to/file.pas

# Interpret the program straight off the AST
make run-interpreter FILE=path/to/file.pas

# Emit the corresponding MIPS code into actual_code_result.asm
# next to the input file
make run-compiler FILE=path/to/file.pas

# (needs fpc installed) compile and run the original Pascal with the Free Pascal Compiler
make run-pascal FILE=path/to/file.pas
```

> For the `run-interpreter` and `run-compiler` targets, an `input.txt` file sitting next to the `.pas` is picked up automatically as the program's standard input (stdin).

A worked example — generate and run the MIPS for one of the test programs:

```bash
make run-compiler FILE=tests/compiler/valid/14-fibonacci/source.pas
java -jar libs/Mars4_5.jar nc ae1 tests/compiler/valid/14-fibonacci/actual_code_result.asm
```

## Running the automated tests

```bash
make test
```

This runs the whole suite: lexer, parser, semantic analyzer, AST, interpreter and the code generator (MIPS + MARS), comparing the output obtained ("actual") against the expected output for every case under `tests/`.

To run a single stage, pass the argument through `ARGS`:

```bash
make test ARGS="--lexer"
make test ARGS="--parser"
make test ARGS="--semantic"
make test ARGS="--ast"
make test ARGS="--interpreter"
make test ARGS="--compiler"
```

The code generator suite can also be run on its own (it compiles each `.pas` to `.asm`, runs the result inside MARS and compares the output against the expected one):

```bash
make test-compiler
```

To clean up the files the tests produced (`actual_result.*`, `diff.diff` and friends):

```bash
make test-clean
```

## Anatomy of a test case

Every test case lives in a subdirectory `tests/<stage>/(valid|invalid)/<case-name>/`, holding:

- **`source.pas`** — the input Pascal program.
- **`expected_result.txt`** (or `expected_result.dot` for the AST tests) — the expected output.
- **`input.txt`** *(optional)* — standard input (stdin) data, used by the interpreter/compiler tests when the program reads input.

Running the tests leaves each case with an `actual_result.*` (or `actual_code_result.asm`, for the code generator) and a `diff.diff` comparing it line by line against the expected output:

- No differences → **`[PASS]`** (and the temporary files are removed).
- Differences → **`[FAIL]`** (the `diff.diff` is kept so it can be inspected).
- No `expected_result` for the case → it is reported as a missing expected output.

## Continuous integration

The `.github/workflows/tests.yml` workflow runs `make test` automatically on *pull requests* against the `main` branch, using JDK 25 and installing Graphviz beforehand.
